POSTMAN API EXAMPLES
====================

Base URL:
http://localhost:8000

For protected JSON requests, add these headers:

Authorization: Bearer YOUR_TOKEN
Content-Type: application/json

Get YOUR_TOKEN from the login response.


1. AUTHENTICATION
=================

REGISTER
--------
Method: POST
URL: /register
Body: raw JSON

{
  "name": "John Doe",
  "email": "john@example.com",
  "password": "password123",
  "password_confirmation": "password123"
}


LOGIN
-----
Method: POST
URL: /login
Body: raw JSON

{
  "email": "john@example.com",
  "password": "password123"
}

Copy the token from the response and use it as:

Authorization: Bearer YOUR_TOKEN


CURRENT USER
------------
Method: GET
URL: /user
Body: none


LOGOUT
------
Method: POST
URL: /logout
Body: none

5. SEARCH AND FILTERS
=====================

Search by keyword:

GET /items?search=wallet

Filter by category:

GET /items?category=electronics

Filter by date:

GET /items?date=2026-09-10

Filter by location:

GET /items?location=library

Filter by status:

GET /items?status=lost

Combine filters:

GET /items?search=wallet&category=wallet&status=lost

Search requests do not need a request body.

7. ITEM STATUS LIFECYCLE
=========================

Normal lifecycle:

Lost -> Found -> Claimed -> Verified -> Returned

Rejected branch:

Lost or Found or Claimed or Verified -> Rejected -> Closed


UPDATE LOST ITEM STATUS
-----------------------
Admin only
Method: PATCH
URL: /admin/lost-items/1/status
Body: raw JSON

{
  "status": "found"
}


UPDATE FOUND ITEM STATUS
------------------------
Admin only
Method: PATCH
URL: /admin/found-items/1/status
Body: raw JSON

{
  "status": "verified"
}

Allowed status values:

lost
found
claimed
verified
returned
rejected
closed

Only valid lifecycle transitions are accepted.

9. IMAGE UPLOADS
================

Important:
Use Body -> form-data in Postman.
Do not use raw JSON when uploading files.
Do not manually set Content-Type. Postman will set multipart/form-data automatically.

Supported formats:
jpg, jpeg, png, webp

Maximum size:
5 MB


CREATE LOST ITEM WITH IMAGE
---------------------------
Method: POST
URL: /lost-items
Body: form-data

Key              Type    Value
category_id      Text    2
title            Text    Black Wallet
description      Text    Black leather wallet
location_lost    Text    Library
date_lost        Text    2026-09-10
image            File    wallet.jpg


CREATE FOUND ITEM WITH IMAGE
----------------------------
Method: POST
URL: /found-items
Body: form-data

Key              Type    Value
category_id      Text    1
title            Text    Blue Headphones
description      Text    Wireless headphones
location_found   Text    Cafeteria
date_found       Text    2026-09-10
image            File    headphones.jpg


SUBMIT CLAIM WITH PROOF IMAGE
-----------------------------
Method: POST
URL: /found-items/1/claims
Body: form-data

Key              Type    Value
claim_reason     Text    I believe this item belongs to me.
proof            File    proof.jpg


10. COMMON HTTP RESPONSES
=========================

200 OK
Request completed successfully.

201 Created
A new record was created.

401 Unauthorized
Missing or invalid bearer token.

403 Forbidden
User is authenticated but is not an admin or does not own the item.

404 Not Found
The requested record does not exist.

422 Unprocessable Entity
Validation failed or an invalid status transition was requested.


11. POSTMAN TESTING ORDER
=========================

1. POST /register
2. POST /login
3. Save the returned token
4. GET /user
5. GET /categories
6. POST /lost-items
7. POST /found-items
8. GET /items?search=wallet
9. POST /found-items/{foundItem}/claims
10. Login with an admin account
11. GET /admin/claims
12. GET /admin/claims/{claim}
13. POST /admin/claims/{claim}/approve
14. PATCH /admin/found-items/{foundItem}/status
15. GET /admin/dashboard/statistics

Admin requests must use an admin user's token.
